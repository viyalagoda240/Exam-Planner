1. Files and access methods

A file is a named collection of related information stored on secondary storage. The OS's file system decides how files are named, stored, organised, protected and accessed.

  • Attributes: name, identifier, type, location (disk blocks), size, protection (owner, permissions), timestamps (created, modified, accessed).
  • Operations: create, open, read, write, seek (reposition), close, delete, truncate.

Access methods

Direct (random / relative)Any block can be read or written directly by its block number, in any order, without reading the ones before it.Databases, airline reservation records
IndexedAn index (like a book index) holds pointers to blocks; first search the index, then jump to the block.Large databases, library catalogues

2. Directory structures

2026 Q5(d) – multi-user system: direct access, tree and DAG (7 marks)

  • Preventing data conflicts: a tree gives every user a separate home directory, so two users can both have report.txt without clashing. A DAG lets users share one real copy of a file through links, so there are no out-of-date duplicate copies.
  • Improving efficiency: direct access lets a program jump straight to the record it needs instead of reading the whole file – fast for databases with many users. A tree shortens searches (only one directory path is searched); a DAG avoids storing duplicates.
  • Maintaining security: permissions can be set on each directory and file in the tree (owner/group/others), so users cannot reach each other's private folders. In a DAG, only the users given a link (and permission) can reach a shared file; reference counts stop a file being deleted while others still use it.

2025 Q5(d) – single-level vs two-level: efficiency and scalability

A single-level directory must be searched in full for every lookup and all names must be unique, so it becomes slow and unmanageable as users and files grow – poor scalability. A two-level directory searches only one user's directory (faster), allows the same name for different users and isolates users, so it scales better – but still offers no sub-folders for organising many files.

I-nodes (2023 Q5(c), 4 marks)

An i-node (index node) is a small fixed-size data structure used in UNIX/Linux file systems. There is one i-node per file. It stores the file's attributes (owner, permissions, size, timestamps, link count) and the disk addresses of the file's blocks: about 12 direct block pointers, plus a single-indirect, a double-indirect and a triple-indirect pointer for large files. The directory entry only maps a file name → i-node number.

Uses / advantages: only the i-nodes of open files need to be in memory (saves RAM); small files are reached quickly through direct pointers while very large files are still supported through indirect blocks; several names (hard links) can point to the same i-node, which makes sharing easy.

සිංහලෙන්: i-node එක කියන්නේ file එකක "ID card" එක වගේ – owner කවුද, permissions මොනවද, size එක, වෙලාවන්, සහ disk එකේ data blocks තියෙන තැන් (addresses) ඒකේ තියෙනවා. Directory එකේ තියෙන්නේ "file නම → i-node අංකය" විතරයි. Open කරපු files වල i-nodes විතරක් RAM එකට ගන්න නිසා memory ඉතුරුයි; ලොකු files වලට indirect pointers තියෙනවා.

4. Free memory management: bitmaps vs linked lists (2023 Q5(a))

Bitmap: memory is divided into equal allocation units; each unit has one bit (0 = free, 1 = used). The bitmap has a fixed size that depends only on memory size and unit size. Simple, but to place a process of k units the OS must search the bitmap for k consecutive 0 bits, which is slow. Small units → big bitmap; big units → wasted space in the last unit.

Linked list: a list of segments, each either a process (P) or a hole (H), with start address, length and a pointer to the next entry, kept sorted by address. Allocation uses first fit, next fit, best fit or worst fit; when a process ends, neighbouring holes are merged easily. The list grows and shrinks with the number of segments, and searching can be faster than scanning bits.

BitmapLinked list
Space usedFixed, known in advanceVaries with number of holes/processes
Finding free spaceSlow – scan for a run of 0sFaster – walk the hole entries
Freeing memoryJust clear bitsMerge with neighbouring holes
SimplicityVery simpleMore complex (pointers)

සිංහලෙන්: Bitmap = memory එකේ හැම කොටසකටම bit එකක් (0 හිස්, 1 පිරිලා). Size එක ස්ථිරයි, ඒත් ලොකු process එකකට හිස් තැනක් හොයන්න 0 දිගටම තියෙන තැනක් scan කරන්න ඕනේ – හෙමින්. Linked list = "process කොටසක් / හිස් කොටසක්" කියලා ලැයිස්තුවක්; හිස් තැන් හොයන්න ඉක්මන්, process එකක් ඉවර වුණාම අල්ලපු හිස් තැන් එකතු කරන්න ලේසියි.

5. File permissions and protection (2025 Q5(c), 4 marks)

File system permissions are rules attached to each file and directory that say who may do what with it. In UNIX/Linux there are three rights – read (r), write (w), execute (x) – for three classes of users – owner (u), group (g), others (o).

How they control access: every time a process tries to open, change or run a file, the OS compares the process's user ID and group ID with the file's owner, group and permission bits, and allows or refuses the operation. Access Control Lists (ACLs) extend this with per-user rules (used by Windows NTFS).

Example: -rwxr-x--- report.sh → owner can read, write, execute; group can read and execute; others have no access. In numbers: chmod 750 report.sh (r = 4, w = 2, x = 1 → 7 = rwx, 5 = r-x, 0 = ---).

සිංහලෙන්: Permissions කියන්නේ file එකකට "කාටද මොනවද කරන්න පුළුවන්" කියන නීති. r = කියවන්න, w = වෙනස් කරන්න, x = run කරන්න. Owner, group, others කියලා කොටස් 3කට වෙන වෙනම දෙනවා. File එකක් open කරන හැම වෙලාවකම OS එක මේ bits බලලා ඉඩ දෙනවද නැද්ද කියලා තීරණය කරනවා.

6. Banker's algorithm

The Banker's algorithm is a deadlock-avoidance algorithm. Before granting a request, the OS checks whether the system would still be in a safe state – a state where there is at least one order (safe sequence) in which every process can get its maximum need and finish. If the request leads to an unsafe state, the process waits.

Safety algorithm steps

  1. Need = Max − Allocation for every process.
  2. Work = Available. Mark every process "not finished".
  3. Find a not-finished process whose Need ≤ Work (every resource type).
  4. Pretend it finishes: Work = Work + its Allocation; mark it finished; add it to the safe sequence.
  5. Repeat steps 3–4. If all processes finish → SAFE (give the sequence). If you get stuck → UNSAFE.

9. BIOS, DMA, I/O addressing and interrupts

Why do computers need a BIOS? (2023 Q2(a))

The BIOS (Basic Input/Output System) is firmware stored in ROM/flash on the motherboard. When the power is switched on, RAM is empty, so the CPU needs a fixed program to start from. The BIOS: (1) runs the POST (power-on self-test) to check RAM, keyboard and disks; (2) initialises the hardware; (3) finds the boot device and loads the bootloader, which loads the operating system; (4) provides basic low-level I/O routines and the setup (CMOS) settings. Modern PCs use UEFI, which does the same job.

DMA (2023 Q4(d))

Direct Memory Access: a DMA controller moves a block of data between an I/O device and memory without the CPU copying each byte. The CPU only sets up the transfer (memory address, byte count, direction) and receives one interrupt when it is finished.

Increases concurrency: while the DMA controller transfers data, the CPU runs other processes – CPU work and I/O happen at the same time.

Complicates hardware: needs an extra DMA controller; the CPU and DMA compete for the memory bus (bus arbitration, cycle stealing); cache contents can become inconsistent with memory; more interrupt handling.

Separate I/O space vs memory-mapped I/O (2023 Q3(c))

With a separate I/O address space (port-mapped, special IN/OUT instructions): the whole memory address space stays free for RAM; I/O instructions are easy to recognise and can be restricted to the kernel (protection); device registers are never cached by mistake; address decoding for memory is simpler. (Memory-mapped I/O instead uses normal load/store instructions on device registers, which is more flexible but uses up memory addresses and needs caching disabled for those addresses.)

Precise vs imprecise interrupts (2025 Q5(e), 5 marks)

A precise interrupt leaves the machine in a well-defined state: (1) the program counter is saved in a known place; (2) all instructions before it have fully completed; (3) no instruction after it has started (or its effects are undone); (4) the state of the instruction at the PC is known. The OS can simply restart from the saved PC.

An imprecise interrupt does not meet these conditions – in pipelined or superscalar CPUs, several instructions may be half-finished. The CPU dumps a lot of internal state for the OS, so interrupt handling becomes slow and complex.

Why busy waiting is a poor way to get mutual exclusion (2023 Q3(b))

A process that busy-waits keeps using CPU time while doing nothing useful (spinning in a loop). It can also cause the priority inversion problem: a high-priority process spins forever while a low-priority process inside the critical section never gets the CPU to leave it. Blocking (sleep/wakeup, semaphores) is better.
