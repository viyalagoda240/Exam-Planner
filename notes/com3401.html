1. Layered network architecture

Networking is split into layers. Each layer does one part of the job, uses the services of the layer below and offers services to the layer above. This reduces complexity, lets different vendors' equipment work together (standards) and lets one layer change without changing the others.

Peers
The entities in the same layer on two different machines. They talk to each other using that layer's protocol (e.g. the transport layer of host A and the transport layer of host B).
Interfaces
The boundary between two adjacent layers on the same machine. It defines which operations and services the lower layer offers to the upper layer.
Protocol
The rules (format, order of messages, actions) that peers use to communicate.
Protocol stack
The list of protocols used by a system, one protocol per layer (e.g. HTTP / TCP / IP / Ethernet).
Encapsulation
Each layer adds its own header (and the data link layer a trailer) to the data from the layer above; the receiver removes them layer by layer.

Why clear interfaces between layers matter (2026 Q3(d)(i))

  • A layer's implementation can be replaced (e.g. Ethernet → Wi-Fi) without changing the layers above, as long as the interface stays the same.
  • Each layer only passes the minimum information needed, which keeps the design simple and easy to test.
  • Different vendors can build different layers that still work together.

Error handling in the data link layer (2026 Q3(d)(ii))

Bits can be corrupted by noise on a link. The data link layer adds an error-detecting code (a CRC/FCS in the trailer, or parity). The receiver recalculates it; if it does not match, the frame is discarded and, in reliable links, retransmitted (ARQ). This stops corrupted data from being passed up to the network layer and fixes errors hop by hop, close to where they happen – cheaper than end-to-end recovery.

The data link layer PDU – the frame (2023 Q4(c), 5 marks)

Flag / preambleDestination addressSource addressControl / typePayload (packet from network layer)FCS (CRC)Flag

The PDU is called a frame. Header: start flag/preamble (marks the beginning), destination and source MAC addresses, control or type/length field. Payload: the network-layer packet. Trailer: FCS (frame check sequence, a CRC for error detection) and end flag.

A mechanism to detect a single-bit error (2023 Q4(d))

Parity check: the sender adds one bit so that the number of 1s is even (even parity). Any single flipped bit makes the count odd, so the receiver detects it. Example: data 1011001 has four 1s → parity bit 0 → send 10110010. If one bit flips, the count of 1s becomes odd → error detected. (CRC also detects all single-bit errors.)

Which TCP/IP layers are implemented in routers? (2025 Q3(d), 4 marks)

Routers implement the network access (physical + data link) layers and the internet (IP) layer – the bottom three OSI layers. A router receives a frame, removes the link header, reads the destination IP address, looks up its routing table and forwards the packet in a new frame on the next link. It does not need the transport or application layers to forward packets (those run only on the end hosts).

Need for an OSI layer 3 in a broadcast network (2025 Q3(c))

Inside one broadcast network (a single LAN or Wi-Fi cell) every station receives every frame, so there is no path to choose – the data link layer with MAC addresses is enough and layer 3 is very thin or not needed. Layer 3 becomes necessary when several networks are connected: it gives logical (IP) addresses that work across networks, routes packets between them and separates broadcast domains.

4. Transport layer: TCP vs UDP and error control

The transport layer gives process-to-process delivery using port numbers, splits data into segments and reassembles them, and (in TCP) provides flow control, error control and congestion control.

Connection-oriented vs connectionless (2026 Q5(b), 4 marks)

Connection-oriented (TCP): a connection is set up first (three-way handshake) and closed at the end. Delivery is reliable and in order – acknowledgements, sequence numbers and retransmission – with flow and congestion control.

Connectionless (UDP): no connection set-up; each datagram is sent independently. No acknowledgements, no guarantee of delivery or order, but low delay and low overhead.

Main difference: TCP guarantees reliable, ordered delivery over an established connection; UDP sends independent datagrams with no guarantee, trading reliability for speed.

Functions of transport-layer error control (2026 Q5(a), 2023 Q5(c), 4 marks)

  1. Detect and discard corrupted segments (checksum).
  2. Detect lost segments (acknowledgements + timers) and retransmit them.
  3. Detect out-of-order segments (sequence numbers) and put them back in order.
  4. Detect and discard duplicate segments.

TCP or UDP for text messaging? (2025 Q5(a), 4 marks)

TCP. A text message must arrive complete, correct and in the right order – a missing or jumbled part changes the meaning. A small extra delay is acceptable for text, so TCP's reliability (acknowledgements, retransmission, ordering) is worth its overhead. UDP suits live voice/video, where speed matters more than a lost packet.

සිංහලෙන්: TCP = මුලින්ම connection එකක් හදලා (handshake), ලැබුණාද කියලා ACK බලලා, නැති වුණොත් ආයෙත් යවලා, පිළිවෙළට ලබා දෙනවා – විශ්වාසයි, ටිකක් හෙමින්. UDP = connection නැතුව කෙලින්ම යවනවා – ඉක්මනුයි, ඒත් නැති වුණොත් බලන්නේ නෑ. Text messages වලට TCP – මැසේජ් එකේ කොටසක් නැති වෙන්න බෑ.

Classful addressing (2026 Q5(c), 2023 Q5(d))

Classful addressing is the original IPv4 scheme where the 32-bit address space is divided into five fixed classes (A–E). The class decides where the network part ends and the host part begins.

2026 gives it in binary: 00010100 00010000 00000100 00010010 = 20.16.4.18; mask 11111111 11111111 11111111 11110000 = 28 ones → /28.

6. Past-paper calculations (worked)

Synchronous TDM – 2026 Q4(e)

Five digital channels × 64 kbps. (i) Synchronous TDM gives every channel a slot in every frame, so the link needs at least 5 × 64 = 320 kbps (ignoring framing bits). (ii) Statistical TDM gives slots only to channels that have data, so the link can be sized for the average load – e.g. if each channel is busy about half the time, roughly 160 kbps plus a little address overhead. The difference: synchronous TDM wastes slots on idle channels; statistical TDM does not.

Why statistical TDM is more efficient (2026 Q4(d), 2025 Q4(d))

In synchronous TDM each input owns a fixed slot even when it has nothing to send, so many slots travel empty. Statistical (asynchronous) TDM allocates slots dynamically to active inputs only, so fewer slots are wasted and the output link can be slower than the sum of all input rates. (Cost: each slot needs an address field.)

Synchronous TDM with a sync bit – 2023 Q5(b)

20 sources × 100 kbps, each output slot carries 1 bit from each source, plus 1 synchronisation bit per frame.

  1. Frame size = 20 × 1 + 1 = 21 bits (frame rate = 100,000 frames/s → output 2.1 Mbps).
  2. Efficiency = useful bits ÷ total bits = 20 ÷ 21 = 95.24 %.
  3. With 2 bits per slot: frame = 20 × 2 + 1 = 41 bits → efficiency = 40 ÷ 41 = 97.56 % (fewer sync bits per data bit).

FDM bandwidth – 2025 Q4(e)

5 channels × 10 kHz, guard band 500 Hz between neighbouring channels → 4 guard bands.

Total = 5 × 10 kHz + 4 × 0.5 kHz = 50 + 2 = 52 kHz

CRC sizes – 2025 Q4(b)

Dataword k = 10 bits, codeword n = 14 bits.

  1. 0s added to the dataword = n − k = 4.
  2. FCS (remainder) size = 4 bits.
  3. Divisor size = n − k + 1 = 5 bits.
  4. A suitable divisor: 10011 (x4 + x + 1) – 5 bits, starts and ends with 1.

Bit stuffing – 2025 Q4(a)

Rule: the frame flag is 01111110. To stop the same pattern appearing inside the data, the sender inserts a 0 after every five consecutive 1s in the data. The receiver removes a 0 that follows five 1s.

Data (27 bits)011111101111101111111111110

After stuffing (31 bits, stuffed 0s highlighted)0111110101111100111110111110110

Sent frame01111110 0111110101111100111110111110110 01111110

Four 0s were stuffed: one inside the first run of six 1s, one after the run of five 1s, and two inside the run of twelve 1s.

Character count framing – 2026 Q4(b)

The first byte of each frame holds the number of characters in the frame (including itself). The receiver reads this count to know where the frame ends and the next begins. Example: 5 A B C D | 3 E F. Weakness: if the count is corrupted, the receiver loses track of every following frame boundary (loses synchronisation).

Radio and TV broadcasting – 2026 Q4(c)

Frequency Division Multiplexing (FDM): each station is given its own carrier frequency band; all stations transmit at the same time through the air, separated by guard bands; the receiver tunes (filters) to one band.

7. Quick answers for short questions

Modem (2026 Q3(b))
MOdulator–DEModulator: converts digital data from a computer into analog signals for a telephone/cable line and back again. A pair is needed – one at each end – because both ends must convert (2023 Q3(a)).
Gateway (2026 Q3(b))
A device that connects networks that use different protocols and translates between them (can work up to the application layer), e.g. connecting a LAN to the Internet or to a different network architecture.
Bridges vs routers (2025 Q3(a))
Differences: a bridge works at the data link layer, forwards frames by MAC address and joins segments of the same network (one broadcast domain); a router works at the network layer, forwards packets by IP address, joins different networks, chooses best paths and separates broadcast domains. Similarities: both connect network segments, store and forward traffic, filter traffic and reduce collisions.
Characteristics used to classify networks (2025 Q3(b))
Geographic size (PAN, LAN, MAN, WAN); ownership (private/public, EPN, VPN); topology (bus, star, ring, mesh); transmission medium (wired/wireless); architecture (client–server or peer-to-peer).
Uses of networks in scientific work (2026 Q3(a))
Sharing research data between universities; remote access to expensive instruments (telescopes, labs); distributed/grid/cloud computing for big simulations; sensor networks for weather and environmental monitoring; online journals and databases; video conferencing and collaboration.
Star topology (2026 Q3(c))
Topology = how devices and links are arranged. In a star, every device has its own cable to a central switch/hub. One cable failure affects only one device and it is easy to add devices, but if the central switch fails, the whole network stops.
